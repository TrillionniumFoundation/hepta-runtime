# Public connection owner scope and production seam

This component owns bounded raw message classification, typed request and
notification projection, persistent modern/legacy handshake, version and
metadata admission, initialize/discovery responses and immutable per-request
peer/context snapshots. It is validated against rmcp 3.4.1 using the original
runtime's exact get_info method and the exact original Cargo dependency closure.
The SDK's `Implementation::from_build_env()` reports `rmcp` / `3.4.1` in the
observed original program. The reference wrapper does not substitute a fixture
package identity for that result.

The native sources are actual HIA, compiled by the pinned d3 compiler. The fixed
native adapter is only the OS and byte-buffer boundary. Python prepares builds,
generates test data and checks evidence; the executable never calls it.

## Qualified domains

The retained direct domain has 4,782 original message cases, including duplicate
keys, nested typed sequences, Options, enum forms, integer/floating IDs, exact
f64 promotion and spelling, malformed UTF-8, depth and byte mutations. Separate
actual transport observations contain 4,804 cases. Native parser results are
checked against every raw frame in that domain; the splitting test driver is
explicitly distinguished from the real adapter tests.

The lifecycle domain has 2,203 original SDK sessions, 6,414 offered events and
6,126 complete responses. It includes every known request method across five
supported versions, true `server/discover`, repeated initialization, both mode
paths and the original metadata/version error priority. Both actual static ELF
processes and the native module chain replay the complete domain. The module
chain also compares real Service request-context and peer-info observations.

The capacity and OS transport controls cover rollback of initial/repeated
initialize, exact output size, corrupt private frames and private state, real
byte-at-a-time input, CRLF/BOM, final EOF frames, exact 8 MiB raw lines, refusal
above that profile, escaped IDs and rejection of a caller-selected mode flag.

## Owners still required for production

The next integration is a native tool registry replacing the test-only default
handler. Its fixed routes must invoke installed config op1/op2 and execution
controller6 through the existing administrator-owned startup chain. Ordinary
tool parameters cannot install configuration, choose an SSH/local authority or
overwrite connection mode. The SDK request parser provides canonical arguments
Value bytes, so the registry must not reinterpret them through the earlier
strict protocol parser.

The production router must keep original Parameters<T> errors before handler
entry and before the first RequestContext latch. Workdir's exact typed owner,
ClientCapabilities, Session Workdir, caller scope, audit/result ownership,
effect fences and each actual tool body remain independent dependencies. A
successful connection handshake does not establish any of those authorities.

The complete asynchronous SDK service still needs its pending outgoing-request
registry, response correlation and typed ClientResult normalization, request
task lifetime and cancellation delivery, subscriptions/resources and transport
shutdown ownership. Response/error messages retain complete original bytes for
that next owner; forwarding alone is not claimed as completed correlation.
Streamable HTTP is outside this stdio profile. The original SDK is not bounded
to 8 MiB lines; that finite native admission bound remains explicit.

The runtime's 125 production tool owners, full-runtime completion, production
activation and removal of the old stack remain unchanged and false. No new
handler is counted as migrated merely because its request name is parsed or
because the SDK default fixture returns method-not-found.
