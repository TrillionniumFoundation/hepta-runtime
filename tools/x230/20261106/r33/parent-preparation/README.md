## Qualification binder interface

The exact CI materializer can import ROOT/tools-01/r33_campaign.py as a non-main
module and call bind_r33_candidate_preparation(inputs, bind). It needs only six
keys, each populated from actual completed evidence:

~~~
qualification_launcher        ROOT/prepare_qualify.py identity
qualification_input           ROOT/input.json identity
candidate_patch               ROOT/combined.patch identity
qualification_preparation     ROOT/preparation.json identity
qualification_terminal_status ROOT/qualification-terminal-status-01.json identity + job_id
qualification_reports         [ROOT/qualification-01/report.json identity + success_field="qualified"]
~~~

An identity is {path, bytes, sha256}. The bind callback uses the existing parent
checked reader and returns an identity normally, or (identity, raw_bytes) for
retain=True. The binder makes no calls to SSH or runtime processes and starts
no monitor. It does not depend on campaign-inputs-01.json or a completed
observation campaign.

The original native terminal file must contain the raw status JSON object
with job_id/state/exit_code/log custody fields, not the outer MCP content wrapper.
Its original bytes and the actual successful job id are supplied only after
native completion. The binder retains the original eight-stage names, no retry,
dynamic isolated-test counts, unchanged harness, pre-format input map, final
formatted tested map, and original stage-log and test-audit input hashes.

## Reproduction and limits

build_bundle.py reads only the pinned reference files and the two source
fragments, performs static comparisons, and creates new outputs. It refuses
existing output files. To reproduce, use a separate directory containing the
same references and source fragments. Do not overwrite this original bundle.

This is qualification and measurement orchestration. It is not evidence that a
future runtime binary has passed or improved throughput. Historical process
inspection and known opaque helper classifications retain their original
limited scope; this package does not turn those into a claim of global machine
idleness. The benchmark and acceptance thresholds remain those of the original
reviewed harness.
