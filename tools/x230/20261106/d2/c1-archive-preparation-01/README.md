# D2 C1 evidence archive preparation

This is an unsealed adaptation of the completed D1 C1 collector. No D2 holder outcome, count, trace, report, archive identity or success is predicted. ACTUAL is None; all four collector entry points reject it. The pure local sealer also requires a real original holder terminal and complete, contiguous stored native pages.

## Selection and capacity

The collector keeps the original fixed capture directories: c1-campaign-01, c1-observation-01, c1-adapter-evidence-01 and c1-holder-originals-01. It retains every eligible original log and raw trace in those directories, plus the declared core receipts and runtime inputs. Credential names/content, symlinks, profiles, source/target test binaries and ELF payloads remain excluded by the unchanged scanner/readers. A direct candidate file may have its first four bytes read to detect an ELF. No original program is executed and verification never extracts files.

The original bounds are unchanged: 384 MiB selected bytes and combined archive/sidecars, 32 MiB per selected file, 2 MiB manifest, 8,192 files and the original expanded-tar allowance. Runtime, parser and adapter limits remain 32 MiB per trace. The existing adapter produces one report bounded at 16 MiB, below the archive's per-file limit. Whole raw events are not copied into that report: its phase values are grouped by request and phase. These source bounds do not assert any future D2 byte count.

Fifteen static pins bind the fourteen frozen D2 parent runtime dependencies, including the D2 parser and correlation module, plus the frozen canonical prerequisite-module copy. ## Original outcomes and correlation

The original thirteen result slots are retained and the four runtime slots bring the core inventory to seventeen. The exact native read pages are additional slots. Missing result files become null and must remain absent during capture. Failed, cancelled, timed-out or partially completed workflows keep their original outcome, parser errors, stage prefix and available raw traces. A successful holder whose required local bodies have not all arrived cannot be relabelled failed merely to bypass the missing mirror.

The successful branch reconciles the existing D2 parent/adapter declarations: the unchanged 936-call matrix, eight original controller closes, 468 ON request bijections, 384 ON measured requests and inclusive validation_worker plus validation_owner whole-cost field. These are existing protocol/result checks. The collector does not run the trace parser, correlation arithmetic, native auditor or monitor validator and does not infer performance adoption. Any binding errors remain in the compact output.

## Sealing and operators

Use operators.unsealed.json for the exact seventeen relative paths and command shapes. Root supplies the completed original holder job ID and exact local mirror. Run the pure local sealer once into a fresh directory; it hashes raw originals, fills only ACTUAL and verifies AST equality outside that assignment. Original JSON bytes are never rewritten. Root then installs the resulting collector under a fresh name and alone creates c1-evidence-01. After immutable transfer, the exact same sealed source verifies the archive without extraction. All output names are create-only; partial errors are retained.

Original Mac output is <holder-directory>/report.json. Copy its actual report.log_files entries byte-for-byte into c1-holder-originals-01 before root invokes collection. The sealer does not require those log bodies; the collector reconciles their actual identities.
