# D2 ordinary evidence archive preparation

This package prepares the first D2 ordinary supplement archive. The original ordinary job `1a1b1014af6-fc05-74d2` has been launched; its complete result and postflight remain unbound. The collector contains `ACTUAL = None` and refuses collection, summary, creation, or verification until the pure local sealer binds actual originals.

## Fixed scope

The twelve fixed inputs are the nine actual ordinary deployment members, the canonical D2 prerequisite module, the completed D2 qualification report, and the unchanged original qualifier. Their exact identities are in `static-originals.json`. Only the current `ordinary-01` evidence directory, eleven core receipts, and original contiguous native read pages are selected. The D1 failed preflight and recovery package are not D2 evidence.

The ordinary protocol remains the five original stages: clippy, test-build, isolated-tests, audit-isolated-tests, release. The original formatter, fmt check, and harness tests are not rerun. Ordinary test counts come from the actual ordinary summary and audit. They are not copied from the qualification count.

## What the archive proves

For a passed result the collector reconciles the original ordinary report, command and stream hashes, all original compressed case logs against the already executed isolated audit, native terminal and original read pages, and the actually executed postflight/native pair. The archived postflight records unchanged 222 compiler inputs, the nineteen original harnesses, and the identities of three qualified feature release programs and three ordinary release programs.

The collector does not import or execute the prerequisite binder, result verifier, isolated auditor, archived programs, or a compiler. It does not rehash debug/test ELF bodies or release ELF bodies. Original auditor custody and the actual postflight's release identity checks are reported with their scope. Q/CI and previous owner bodies outside this narrow archive remain explicit external input identities.

For a failed or incomplete original attempt, missing core receipts are pinned as absent and malformed JSON is preserved with parse-error metadata. A successful producer is not sealed while the actual postflight is still pending. Nonzero results are not converted into success.

## Bounds and privacy

The original limits are unchanged: 32 MiB selected bytes and combined archive/sidecars, 8 MiB per selected file, 2 MiB manifest, 8192 selected files, with the original bounded expanded-tar calculation. Stable no-follow reads, exact member hashes, content scanning, create-only outputs, and zero-extraction verification remain in place. Test-binaries, target/profile/credential subtrees and ELF bodies are excluded. The collector and sealer sources themselves remain Git preparation objects outside the selected archive scope; the scanner is not weakened or bypassed.

The two original D1 reference scripts are preserved in Git. The new source is generated by the recorded exact text replacements, and reversing the ledger reconstructs both reference scripts byte for byte. Twelve selected static bodies were rehashed. The first local syntax-only request did not start because the executor rejected process creation; that is recorded in `static-checks.json`, not reported as a successful AST check or a collector execution.
