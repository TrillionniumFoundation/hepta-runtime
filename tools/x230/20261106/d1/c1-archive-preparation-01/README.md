## Caps fixed before result capture

| Bound | Value | Source/rationale |
|---|---:|---|
| Selected payload total; combined compressed archive and sidecars | 384 MiB | A conservative 8 × 32 MiB raw-trace allowance plus 128 MiB for other original evidence; the total is an independent hard cap |
| Individual selected file | 32 MiB | The original Rust writer and adapter cap a raw trace at 32 MiB |
| Manifest | 2 MiB | Existing bounded inventory size |
| Files | 8192 | Existing bounded inventory count |
| Original native pages | Up to 16, contiguous | Existing native-page helper: full stored stdout/stderr, at most 256 KiB per stream |

Actual formatted diagnostic Rust source (Git `1bb1a0567d8571a650a2aaa373faa50d968b4c44`, 23,949 bytes, SHA256 `06e5fc3892290fa5ab9d034c7d5bef041a18105a2808342eb51fc9c82e69e882`) fixes 32,768 events and 2,048 request slots per controller and a 32 MiB output cap. There is no independent per-request event cap. The 18 synchronous instrumentation positions must not be multiplied by request count as a purported hard size proof. The original adapter reads each transport/index/report under a 16 MiB bound; the C1 archive's 32 MiB per-file cap also preserves partial originals without imposing that successful-reader condition on failure captures.

These bounds do not assert that every possible member can simultaneously reach its individual maximum. If any real input exceeds a fixed bound, the collector rejects without truncation or an automatic cap increase; original files and the failed collector receipt remain available. In particular, an incomplete trace is preserved as original evidence and is not rewritten into a complete trace.

## Seal and execute only after the original terminal

The sealer performs local reads, JSON/AST processing and the existing pure native-page validation. It does not import the collector or run its summary, any verifier, original auditor, trace parser, runtime, build or host request. It changes only the unique `ACTUAL` assignment and proves full AST equality after replacing that assignment back with `None`.

```text
/usr/bin/python3 -B seal_c1_archive.py
  --template archive_d1_c1.py
  --originals /absolute/actual-c1-original-mirror
  --holder-job-id ACTUAL_ORIGINAL_HOLDER_JOB_ID
  --output /absolute/new-sealed-output-directory
```

Root installs the exact sealed collector bytes once at `ROOT/archive_d1_c1_01.py`, verifies the full SHA, and owns the single future collector launch:

```text

```

## Interpretation boundaries

The compact report reconciles captured original identities, raw transport/resource/trace hashes, original native/holder closure, two original stage receipts, eight original controller closes when completed, original auditor/monitor claims and reported counts. Failed or partial parent/adapter/auditor outcomes are retained; parse/binding errors are recorded and never upgraded to a pass. All raw originals remain in the archive independently of compact conclusions.

`diagnostic_passed` means the actual original diagnostic workflow reported success and the recorded evidence was captured. `captured_originals_binding_verified` is a receipt reconciliation result. Neither means a new native audit, trace interpretation, performance acceptance or candidate adoption. Both `performance_acceptance_claim` and `candidate_adopted` stay false. Source/ELF/current-host states are not independently re-probed by this archive; the exact original parent evidence is preserved.
