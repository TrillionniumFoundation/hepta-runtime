## Concrete source fix

`src/mcp/runtime/jobs.rs`: previous `find_idempotent` returned the **first** durable job record with matching host/key. If prior migrations, corruption recovery, or competing controllers left multiple records under the same key, a new `process_start` could silently ignore a second possible physical effect. `select_idempotent_record` now refuses multiple matches with a hard error instead of manufacturing a unique owner. Existing single-owner behavior and host isolation remain unchanged.

Additional changes:
- `src/mcp/runtime/jobs_tests.rs`: in-memory duplicate-owner rejection, host isolation, and real `save_record_at`/`scan_records_dir` duplicate-owner regression tests.
- `docs/HEPTA_RUNTIME.md`: manual reconciliation requirement, and explicit statement that multiple independent state directories are **not** coordinated by the current single-directory owner lock.

The preexisting `controller.owner.lock` already serializes controllers sharing one canonical state directory; an initially considered per-idempotency-key file lock would have added unnecessary files and performance overhead, so it was **removed**. No additional Tokio dependency, file lock or hot-path I/O appears in the final PR diff. The PR diff was independently read back and contains exactly these three paths.
