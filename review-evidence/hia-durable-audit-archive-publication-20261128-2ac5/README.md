# Native audit v12 metadata publication

The HIA actor implements the original initial intent, monotonic subsequent intent, and layout-anchor publication paths. It calls the complete actual metadata reader on the same borrowed root before a subsequent update. Root/legacy identities, the prior shard prefix and the one-shard growth rule retain the original error order.

Canonical JSON is serialized after create-new temporary creation. The original 65536-byte JSON bound, exact write-all behavior, file fsync, link/unlink or rename, directory fsync, and first-error-preserving cleanup remain in HIA. Initial and anchor writers retain their typed input domain. The reader's 256-entry restriction is not incorrectly imposed on the writer: the original 256-to-257 update is preserved. Mechanical workspace capacity holds the complete input without a new shard-count cap.

The HIA packer emits the fixed syscall capability. The actual tests use those emitted bytes in a sealed RX mapping; GNU as/ld are only the independent byte oracle. A single private owner serializes capability entry calls. The borrowed audit root is never closed or exported. Metadata children use that same retained descriptor, bind the full request and action, and prevent destruction/replay while pending.

## Preserved failed and predecessor attempts

The first writer source included an unnecessary fixed typed-vector bound. It was caught before behavior qualification and replaced with capacity-derived complete-input storage. Its complete source and native construction are retained.

The first packer author accidentally used sorted dictionary key order in its five-entry header. The complete predecessor and output are retained; current construction fixes create/step/child_ack/take/destroy order explicitly.

The first filesystem run stopped because the new qualifier omitted the original parser's exact empty-JSON EOF error from its classification. The second ran all 91 cases but rejected one fixture comparison: each independent physical root had a deliberately invalid inode-plus-one in the old record. Both actual implementations returned the same binding refusal and left their complete file snapshots unchanged. The final qualifier permits only that declared relation, requires the full snapshots and exact rejection point to remain unchanged, and includes four counter-controls for other identities/fields. Production HIA and capability bytes did not change between those filesystem runs. All emitted records from both failed runs remain in the archive; no unrecorded intermediate observation is reconstructed.

Special fixtures retain their real modes, symlinks, FIFOs and read refusals. Their exact authored bytes, complete before/after observations and readable byte originals are preserved without chmod or repair.

The content-addressed archive maps every logical original to its complete bytes, SHA256, mode and physical capture. Every member was read back, and the selected physical sources were checked again before commit.

Shard layout initialization/restart, the shared archive registry, redb persistence and the ten public Durable Requests handlers continue separately. This publication checkpoint does not claim those paths complete.
