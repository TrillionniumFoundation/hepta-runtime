# Shared native SSH owner: retained original 19-method qualification

This checkpoint promotes the five unchanged HIA policies and the mechanical owner
sources. It does not yet replace the default foreground file owner.

## Exact scope and result

The original Rust baseline completed all 19 methods plus the original Linux
parent-death helper (20 raw entries), with default test parallelism. The native
adapter then completed exactly the same methods and helper in 1.647907306 seconds:
20 passed, zero failed, zero ignored, zero retry. Internal 250 ms deadline, 3 s
parent-death reap, 5 s test waits, 8 s fixture backstop and the original 180 s outer
qualification boundary were unchanged. The helper remained a real subprocess of
the original parent-death driver.

The original method file has one import-only preparation: `std::process::Stdio`
becomes the mechanical adapter's `Stdio`. Every method, assertion, fixture and
deadline is otherwise the complete original byte sequence. The entire entry-test
file is unchanged. Full inverse checks and both complete originals are included.

Five HIA images were rebuilt with the fixed d3e2 compiler and matched every original
qualified byte and SHA. Their policies own request admission, the original child,
shared owner registry, I/O policy and caller-future policy. A private owner factory
makes the original test's independent Owner instances explicit; the default
runtime must select one shared instance for its sessions.

The Rust adapter is qualification machinery only: it transports fixed command
frames, exposes actual native state to the retained tests, and runs the original
Entry/Gate/fault callbacks on an ordinary OS thread. Native clone threads never
enter Rust, TLS, allocators or unwinding. Actual fork/exec, pipes, signals, waits,
registry transitions and persisted join results remain in the native owner.

The original injected owner panic occurred and its cleanup assertions passed.
The hidden-wait fixture stores the actual successful wait's PID/status before
returning EIO. Its explicit test cleanup consumes that cached receipt without
another wait or signal and leaves the persistent failed join unchanged.

## Evidence and original failures

The ROG archive contains 4215 complete files / 240971997 logical bytes, including
all source, captured original-lock dependencies, compiled target, test executable,
stdout/stderr and 19 complete recorded journals. Every one of 22763 recorded HIA
frames was structurally read back with its immutable input and complete
before/after workspace/output. Source bytes/modes matched at both boundaries.
No adopted process remained after the test.

The fixed Rust oracle used the original complete Runtime graph. The adapter's
smaller 50-package QA dependency graph preserves exact versions/checksums and
actual original features for its seven direct dependencies, with original Cargo
profiles. It is explicitly a projection, not a claim to have rebuilt the entire
360-registry-package Runtime graph.

Earlier failures are preserved: the first generic build lacked a required captured
helper, and the second completed all five images plus native objects but failed
an English-only readelf-output assertion on a Chinese-locale host. A separate
binary-ELF readback verified the unchanged completed images, relocations,
dependencies, permissions and exports. Neither failure is rewritten as a pass.

`verify_evidence.py` reconstructs each archive from its SHA-bound parts and checks
every member's full bytes and mode. The complete raw archives contain the original
commands, process identities, before/after inventories and receipts. No product
tests are rerun by the verifier.

## Remaining integration

Default file3 currently retains its previously verified installed-config/real-SSH
route. The generic owner will be connected to that same process-owned context,
then the actual default public requests and lifetime boundaries will be exercised
again. REA worker transport requires its own explicit policy: its streaming reply,
stderr probe and sole-reader joins are not covered by SSH's fixed 8 MiB capture.
The broader public 136-handler set, runtime cutover and final branch cleanup remain
open. The current external OpenSSH route may invoke administrator-configured
transport software; that is distinct from the HIA business implementation.
