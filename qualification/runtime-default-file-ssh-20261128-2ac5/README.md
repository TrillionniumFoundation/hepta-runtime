## Ownership and the default event loop

The process text hub owns the private SSH root. Each request owns a copied
transport frame, HIA workspace, output storage and an actual clone thread.
The root retains outstanding requests after a caller disappears. A call can be
released only after the HIA original-child Finish and the kernel clear-TID
join have both completed. Request cancellation and process shutdown are separate
inputs to the same HIA registry. There is no new application queue limit.

Private slots 71 through 77 contain the file gateway, typed parameters, transport,
policy, result decoder and fixed worker boundary. Their descriptors and suspended
continuations are detached into the existing per-request node and restored
together. Public JSON supplies no executable, descriptor, PID, callback or
capability pointer. Installed config operations 9, 10 and 12 supply the admitted
path, host and file executable identity. Job operation 11 does not inherit these
file permissions.

The worker's public-to-its-owner mechanical API is serialized by the single
default event loop. Worker threads perform captured HIA operations and wake the
event loop; they do not release call mappings. A different caller must preserve
this API ownership rule. Arbitrary concurrent \`cancel\` and \`release\` calls on
one freed pointer are not part of this qualification.

## Retained failures and the concrete correction

The first default build encountered a localized \`readelf\` message and was
rejected by the existing relocation guard. The succeeding build fixed only the
build-tool locale; the guard was unchanged.

The first actual public call then exited 111. The complete original run and
three diagnostic attempts are retained. GDB v1 accidentally selected the
no-config domain and is a failed diagnostic. GDB v2 reproduced the resource
return. GDB v3 located the concrete rejection: the installer used engine+32 as
an environment pointer, although that original field is \`AT_SECURE\` and is
normally zero. The correction preserves engine+32 and stores the true process
environment, already captured from the kernel stack, at the previously unused
hub+240. The root borrows that environment for its process lifetime.

No completed or uncertain invocation was replayed as if it had succeeded. The
new default build and public gate have distinct directories and exact inputs.
All earlier component failures, source-author failures, native build failures,
diagnostic outputs, and actual completed results are included in the evidence
archives described by \`qualification.json\`.
