# Five binary parameter owners

These HIA owners project the unchanged current FileInfoParams, BinaryReadParams, BinaryWriteParams, BinaryUploadParams and InodePatchParams declarations. They accept only canonical Map<String, Value> bytes produced by the actual installed serde_json_span HJSMS002 operation. Their private interface carries no caller authority, root permission, filesystem effect or remote command.

Input is 24 bytes followed by the canonical JSON object: HBPRQ001 at 0, JSON length at 8 and kind at 16. Kinds 1 through 5 correspond to file_info, binary_read, binary_write, binary_upload and binary_patch_inode. Each owner accepts only its own kind. Invalid private framing returns 0xffffffff; output shorter than 256 bytes returns 0xfffffffe, without changing output or workspace.

An admitted return is 256, not the complete payload extent. HBPRR001 begins the 256-byte result. Status at 8 is 0 success, 1 typed error, 2 workspace growth, 3 output growth or 4 extent refusal. Kind is at 16. Success fields are action at 24; optional-present bits at 32; acknowledgement/preserve flags at 40; offset, limit and size at 48, 56 and 64. Error byte count is at 72 and required capacity at 80. String byte lengths at 88 through 144 describe host, path, data_base64, expected_version, upload_id, sha256, transaction_id and expected_sha256 in that order. Payload concatenates these strings; on error it contains only the full original typed diagnostic. Bytes 152 through 255 are reserved zero. Non-success frames zero all success fields, while retaining their kind.

Optional-present bits use field numbers: data_base64 3, expected_version 4, sha256 6, expected_sha256 8, offset 9, limit 10 and size 11. These bits distinguish None from Some(empty) or Some(0). The flags use bit 0 for acknowledge_non_atomic and bit 1 for preserve_special_bits. Upload action values 1/2/3 are chunk/commit/abort; inode action values 1/2/3 are apply/status/recover. Other kinds have action zero. Numeric values retain their complete unsigned 64-bit representation.

Workspace demand is max(input length, 512) + 65536. Growth retains all existing workspace bytes and appends zeroes. Output tails beyond the published extent remain unchanged. The owner initializes the first 1024 scratch bytes and a 512-byte field table at offset 65536; retained original decoding helpers use their original scratch ranges below the table. A successful typed projection applies no body size cap, base64 validity check, host lookup, path check, version check or non-atomic acknowledgement policy. Those operations retain their original position in each caller.

Every raw argument first passes through actual native root-Map admission. This private qualification does not register any public tool or establish complete runtime migration.
