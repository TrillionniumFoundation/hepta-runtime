# HIA structured diagnostic formatter

The entry consumes one complete HBRDS001 or HMDSR001 kind-3 frame. All 25 functions of qualified binary_error c322a1f4cfe9346b73f1cd1690f461edfbecd0a6 are retained exactly as IR; the old entry is renamed f25 and a new dispatcher occupies f0. Non-HMDSR001 inputs call that unchanged legacy entry. In particular, HBRDS001 filename kind 2 remains invalid.

HMDSR001 has a 64-byte header: kind at 8 must be 3; sequence at 16 is opaque; wire class at 24 is 1..14; errno at 32 is 0..4095; literal length at 40; filename kind at 48; full payload length at 56. Errno zero requires filename kind 0 and a valid UTF-8 literal whose complete size equals both lengths. Nonzero errno requires zero literal length, the legacy errno-to-wire-class mapping, and either kind 0 with no payload or kind 2 with exactly eight little-endian bytes of unsigned integer FD data. Kind 1 is invalid in HMDSR001. This pure formatter grants no descriptor authority and performs no OS operation.

Integer FD data is rendered in decimal after colon-space, without quotes. The full u64 data domain is supported by bounded decimal operations; no wire input can select a callback, code pointer or operating-system action. Diagnostic class, errno messages, literal UTF-8 validation, frozen Unicode 15.0 platform data, 12,288-byte workspace and output rules are inherited. The return is the complete UTF-8 diagnostic byte length, without a trailing newline; 0xffffffff means malformed input, 0xfffffffe means insufficient capacity. Invalid input leaves both buffers unchanged; short workspace leaves both unchanged; short output may install only the unchanged frozen platform pool in workspace. Successful output leaves all unused output and workspace tails intact.

This package authors source only. It neither compiles nor executes HIA, does not claim CPython equivalence and does not change any public route. Generated bytes must be separately frozen and independently qualified before admission.

The metadata native bridge bounds each borrowed descriptor to 0..2147483647 before invocation. Negative signed descriptors encoded as u64 are rejected by that bridge. A closed but nonnegative descriptor may still yield a real EBADF. Formatter coverage of the full u64 data domain does not widen the metadata bridge's descriptor authority.

## BlockingIOError integer constructor semantics

For errno 11, 114 and 115, CPython interprets the third integer constructor argument as characters_written instead of filename. The HMDSR001 integer-data branch therefore omits the filename suffix. If the unsigned data exceeds SSIZE_MAX (9223372036854775807), the constructor itself raises ValueError with `cannot fit 'int' into an index-sized integer`; the formatter returns that exact top-level diagnostic. Workspace admission and untouched output-tail rules are unchanged. The metadata descriptor bridge's actual FD domain remains 0..2147483647, so this larger-integer constructor case is pure formatter input coverage only. The old HBRDS001 string filename path is unaffected.
