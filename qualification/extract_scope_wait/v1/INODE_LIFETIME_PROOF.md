# Numeric inode reuse proof for the frozen Local WAIT domain

This is a proof about three captured cases, not a general filesystem identity rule. The original full snapshots and all native full snapshots remain unchanged. Every field is still compared. The old reader's permanent map from the numeric (device,inode) pair to one lifetime label is replaced only after the following observed conditions establish a new object lifetime.

The domain admits exactly two valid extract requests and one controlled lock hold/release. The modern invalid opener is excluded only when its exact frozen label, from_path:[] arguments and actual -32602 response are all present. There is no other admitted mutating actor. Both target generations have nlink1, no filesystem aliases, and the temporary path is absent at every observed barrier. All other files retain their entire raw metadata and bytes; the held root keeps the same identity.

Each completed HIA atomic workspace records phase100, sequence6, operation8, zero native rename errno and success ACK1. Full accepted request input, complete replacement bytes and actual native SYS_rename source/target paths are bound. The temporary FD has been closed and is -1; the read FD ownership token is zero. Two independent request contexts exist, the first retires before the second is restored, and complete retired/completed workspaces and output buffers agree. Final size equals the complete second replacement. Thus the second successful rename installs a distinct lifetime even if the kernel allocates the numeric inode formerly used by the removed target.

The native lifetime label changes only at the actual settled lock barrier justified by these events. The complete resulting identity relation must match the original relation. No dev/ino field or other metadata field is omitted. This does not justify extending the proof to hardlinks, unobserved external actors, arbitrary races or other cases.

Five negative controls change exactly one complete captured 8-byte field: success ACK, errno, operation, temporary FD token, or read ownership. Every gzip and outer receipt is honestly resealed. The previous selected full capture reader accepts these otherwise intact records; the new lifetime proof rejects the corresponding exact missing precondition. The three affected cases yield15 independently rechecked semantic refusals.
