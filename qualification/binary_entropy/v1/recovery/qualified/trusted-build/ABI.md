# Process-lifetime entropy and UUID4 owner

HENTQ001 is a 96-byte request: command 1 start / 2 resume at 8, sequence at 16, mode 1 (16 raw bytes) or 2 (32 lowercase UUID4 hex bytes) / signed raw syscall return at 24. All words 32 through 80 are zero and 88 is the full payload extent. Start has no payload. Resume carries at most 144 bytes and must match the outstanding sequence; an output-capacity retry must match every accepted resume byte.

The HIA work arena is at least 1,024 bytes. Offset 64 is the sticky getrandom availability flag, 72 the cached device FD (MAX means absent), and 80/88 its bound st_dev/st_ino. These four words survive each new application; phase 0 or 99 alone admits a next start. The trusted graph must install one serialized entropy context per process, keep it for the process lifetime and supply the common process orphan pool. No public wire grants a caller FD authority. No per-call reset or destruction may discard the cache or getrandom availability state.

HENTR001 is a 64-byte response. Kind 0 is completion with every raw/hex byte; 1 requests a fixed syscall; 3 carries a complete nested HBRDS001 error frame; 4/5 request work/output growth with required extent at 32. Entry return is 64, and the complete payload extent is at 56. Requests carry sequence 16, op 24 and arguments 32/40/48. Operation 1 is getrandom(count=a, flags=0), 2 opens the fixed /dev/urandom path read-only and CLOEXEC, 3 fstats an owned cache/candidate FD (full 144 bytes), 4 closes only an owned candidate FD, 5 reads an owned cached FD (count=b), and 6 transfers a forgotten cached FD to the shared append-only process pool without closing it.

The HIA owner retries EINTR for getrandom/open/read. Both cached validation fstat and initial _Py_fstat are single calls: cached failures forget without closing; initial failures close the new candidate once, preserve the original exception and do not let close failure replace it. getrandom ENOSYS or EPERM permanently selects fallback and resets the partial result to request all sixteen bytes from the device. EOF reports the exact remaining byte count. Opening the device with ENOENT/ENXIO/ENODEV/EACCES reports NotImplementedError. Other open errors keep their /dev/urandom filename; other OS failures have none. New private literal classes are 16 NotImplementedError and 17 RuntimeError; an outer HIA error renderer must explicitly support them. The first 16 random bytes are changed only at UUID version and variant bits when mode 2 emits hexadecimal.

This source checkpoint proves no actual native applications yet. Full actual target/kernel capture, process-global continuity, device-cache loss, faults, FD0, UUID bits, buffer admission and independent retained-evidence reading are required before production integration. This serialized Linux x86-64 owner does not claim arbitrary Python signal handlers or allocation-failure equivalence.
