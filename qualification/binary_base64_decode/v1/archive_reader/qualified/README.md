# Native HIA strict Base64 decoding

This production leaf implements the exact reachable UTF-8 string call made by binary_file.py: base64.b64decode(value, validate=True). It does not impose the outer caller's decoded chunk limit. The 19-function HIA source retains only the prior load, put and UTF-8 utilities by inverse exact-IR relocation. New decoding and diagnostic decisions are HIA.

The frozen input-only domain contains 11,918 semantic inputs in 59 process groups and 503 private ABI calls. Every semantic result is captured independently from actual pinned CPython 3.12.3 and the native B3-compiled HIA image; the pure reader compares full result frames, output tails and every workspace byte. No decoder is run by the reader. Nine physically changed captures and two complete relocations exercise admission and comparison failures. Complete process streams, interpreter (including its built-in binascii)/library bytes, compiler closure, copied prior B3 receipt, original/native buffers and all successful or failed reader proofs are retained losslessly.

Source preparation and build perform zero application calls. Application processes are bounded by 60 seconds, compilation by 900 seconds, pure readers by 180 seconds and the workflow by 15 minutes. An UNKNOWN application cannot be replayed. The immutable original and native captures are never regenerated for a pure-reader repair. Production source and required dependency installation are distinct from qualification drivers; this leaf alone does not close the public write/upload routes.
