read failures separately. A denied descriptor listing no longer discards

## Recovery design and original-child custody

Four controlled counterexamples were observed on x230: an inherited advisory
lock can be released while the original writer remains live; checked socket
and symlink names can be replaced before `unlinkat`; a checked empty directory
name can be replaced before `rmdir`. All examples used fresh owned fixtures,
and all those fixtures were cleaned. The experiment did not inspect or delete
the historical A26 socket residue. See the
[counterexample result](evidence/x230-a27/recovery/counterexamples-result.json).

The [socket custody design](X230_A27_SOCKET_CUSTODY_DESIGN_20261024.md)
separates retained original-child capabilities, stopped admission and terminal
writers, namespace exclusivity, and exact deletion scope. Persisted PID values,
nonces, path age, or an acquired advisory lock alone do not establish all four.
The durable ledger protocol and crash matrix preserve uncertain states and
do not permit RPC replay or adoption of an ambiguous old root.

A separate three-process slice made one part concrete. An already-running
owner created a fixed controller client and one fixed socket writer. It kept
their original `Popen` objects, pidfds, and the root directory descriptor.
After one SIGKILL through the original controller's pidfd, the owner confirmed
controller termination and reaping, then observed private-channel EOF while
the original writer was still live. It sent SIGTERM through that writer's
original pidfd, received the expected notice, and confirmed exit zero and
reaping. The same socket was **retained**.

All fourteen checks and the seven-event sequence passed. The
[execution report](evidence/x230-a27/custody/report.json) and
[independent review](evidence/x230-a27/custody/independent-review.json) retain
the limited scope: one request, a pre-existing owner, no competing admission,
no real SSH master, no owner-crash test, no production owner-startup test, no
same-UID namespace exclusion, and no old-root reclamation. Five-second
protocol/wait budgets do not promise bounded completion of blocked kernel I/O.
Private identity records remain on x230 and are referenced by hashes in the
public report.

## In-progress fixed experiment: archive-query preparation

The isolated candidate removes unused hot-record clones from `usage_stats`
and `archive_history` preparation. A warm cache hit still obtains the original
archive authority and a fresh exact hot-store stamp. A miss invokes the
unchanged full validation/seeding path, with an additional stamp and cache
lookup that must be measured. `STORE_LOCK`, the shared eight actual closure
limit, the original three-second API deadline, and cancellation ownership do
not change.

The [frozen experiment plan](evidence/x230-a27/archive/PREDECLARED_PLAN.json)
declares 49,152 timed public-API queries over 16,384- and 65,536-record
archives at C1/C4/C8, plus 768 warmups, 1,024 cold-guard calls, and eight
setup verification calls. Both arms use complete release source with identical
probe hooks; their sole production difference is the candidate helper and its
two callsites. Process CPU is measured around complete query waves, including
actual closure completion. Allocation counts and allocated bytes are not
measured. The frozen runner records attempted cells and resource-error logs;
the active run's final result is not yet available at this checkpoint.

All six size/concurrency mixed shapes must pass the declared CPU improvement
gates, with separate per-query latency/CPU and cold-miss guards. Passing that
diagnostic experiment would still require normal all-feature formatting,
strict Clippy, tests, release qualification, and independent source/artifact
verification before a runtime source adoption. This checkpoint records the
frozen candidate and tools; it does not pre-announce a performance result.
