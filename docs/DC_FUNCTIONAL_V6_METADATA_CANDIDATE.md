# Native v6 configuration and request metadata candidate

This source candidate adds `effective_config` and `request_history` to v5's bounded batch reads, configured-host health and durable search. It is not installed and is not full Desktop Commander replacement qualification. The installed native runtime and ChatGPT app remain the frozen v4 baseline; Desktop Commander remains the rescue channel.

`effective_config` uses a typed allowlist: configured host aliases, platform/mode, authorization switches, capability counts and bounded summary limits. It never returns SSH destinations, private paths, credentials, environment values, privileged commands, raw policy or a policy hash. It performs no target probe and grants no configuration mutation. The actual MCP result envelope is bounded to 256 KiB and 256 hosts.

`request_history` records only server-generated request identity, canonical tool name, admission time, elapsed dispatch time and an observed state. The central native handler records intent before dispatch, covering unknown tools, runtime-mode refusals, typed parameter failures and handler results. Untrusted request IDs, names, `_meta`, parameters, output, error text, paths and credentials are absent from the metadata DTO. The separate store uses descriptor-relative no-follow access, private 0700/0600 inodes, single-link regular files and bounded records: 512 globally, 128 per native session, 32 per page and a 64 KiB actual MCP wire envelope. Expired and other-session cursors are refused rather than silently skipped. History is live, not an immutable snapshot.

The owner is a native MCP session. The current private facade shares a backend native session, so this does not prove authenticated ChatGPT caller isolation, existing process/job caller ownership or secure cross-session/restart resume. Malformed transport envelopes and facade-local refusals are outside native dispatch history. Accepted is a live observation; crash/drop leaves an unknown durable intent. Completed means a handler generated a normal response: it does not prove response delivery, remote operation success or business completion. Mutating handler errors and cancellation observations are conservatively unknown. Elapsed time excludes client networking, intent publication, result delivery and background job runtime.

Audit completion failure never replaces the original dispatch result or triggers retry. A failure before atomic publication leaves the prior unknown intent; a directory fsync failure after rename may leave a visible terminal record with unconfirmed durability. Never assume every finish error physically leaves Unknown.

Durable process start/reuse/cancel now retain actual results and the same job ID if post-operation audit or local completion persistence fails. Failed intent admission refuses remote submission. Lost remote replies are `launch_unknown`/`cancel_unknown`, with non-authoritative status and no automatic retry. Operator requests never relaunch an uncertain old identity. The isolated administrator-pinned jobctl still reconciles the same ID and full digest; reused supervisor state is preserved instead of falsely labeled launched. `audit_recorded` refers to the separate legacy job-operation completion log, not the new request ledger or result delivery. Remaining legacy post-effect audit paths, including host signals, are still an explicit audit gap.

The optimized candidate passed strict formatting/lint, 472 Rust tests (11 conditional tests remain ignored by default), 19 batch helper tests, 7 search worker tests and 12 replacement-gate tests. It passed native metadata/configuration acceptance and the actual six-host health, batch, search, operator/PTY/stdin/cursor/cancel/temporary-restart matrix, plus all predecessor file regressions. Original v4's 50 definitions and every v5 definition remain exact. The new frozen catalog is a contract boundary, not replacement evidence by tool count.
