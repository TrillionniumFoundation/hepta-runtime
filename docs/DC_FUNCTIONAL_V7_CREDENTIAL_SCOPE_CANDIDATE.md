# Native v7 private credential metadata scope candidate

The candidate fixes loss of retained request history and search metadata when a private HTTP client reconnects or a disposable controller restarts. Ownership comes from the verified private operator credential. All holders of that credential share its metadata scope. This does not authenticate a ChatGPT user, conversation or platform caller.

The HTTP authentication middleware injects a non-serialized typed scope only after the existing constant-time credential check succeeds. Native tools read that extension from the SDK's HTTP request parts; request parameters, headers claiming a caller, client capabilities and `_meta` cannot select ownership. HTTP requests missing the trusted extension fail closed. Each native session fixes its tool-dispatch authority when its first tool call is admitted and refuses a different credential scope. Stdio keeps the previous random native-session owner.

The opaque retained owner is derived with a domain-separated SHA-256 over the private credential. It is never returned or printed by its Debug implementation. Keeping the credential permits retained metadata and cursor access after native reinitialization; rotating it and restarting the controller creates a different owner and refuses the old records. Existing random v5/v6 or stdio owners are not migrated. This is metadata resume with a new native session, not restoration of an old MCP transport session or a running program.

A search receipt left unfinished by a controller restart becomes `interrupted`; lookup and stop do not launch or replay it. Previously observed terminal snapshots remain accessible to the same credential. Unknown durable request intents remain unknown. Returned scope fields explicitly deny authenticated ChatGPT caller isolation and automatic replay. Job and PTY ownership remain the existing trusted operator-account scope.

The token loader now opens the final path once with no-follow, close-on-exec and nonblocking flags; validates the descriptor as a same-account, single-link 0600 regular file; bounds and validates printable ASCII credential bytes; and checks metadata again after reading. It rejects group-readable credentials, symlinks, hard links, special files and unsafe input without returning the path or credential.

Every retained search results/read, list and stop path rechecks the current administrator host binding and read-root policy before returning receipt metadata, including terminal and interrupted fast paths. Revoked roots or hosts cause a generic refusal and are omitted from listing; no old root, search id or target RPC is returned. Path-free request history remains the same-credential historical dispatch ledger.

The actual serialized MCP metadata envelope is limited to 64 KiB. Oversized search reads fail with a request to reduce the page limit. If scope annotation fails after search start or stop, the result preserves a bounded existing search identity, observed state and relevant stop flags with `automatic_retry=false`, so it can be reconciled rather than relaunched.

The new v7 contract changes only the five history/search definitions; the original fifty v4 definitions are exact. Frozen v4, v5 and v6 catalog files remain unchanged. Historical v6 native metadata acceptance assumes native-session-only ownership and is not presented as the v7 ownership gate.

Final validation and hashes are sealed in `docs/qualification/dc-functional-v7-credential-scope-candidate-20261013.json` and its evidence directory. The final source passes formatting, strict clippy, 479 Rust tests (11 conditional tests remain ignored), and all twelve dedicated native checks. The native acceptance uses throwaway credentials and disposable controllers, probes configured six-host SSH health sequentially, and runs two real localhost SSH searches under test-owned roots. A controller-local SSH admission stall faults one real native host_health dispatch before a disposable controller is killed; that injected transport condition is not claimed to be a production target outage. Actual restart preserves its unknown request and interrupts the locally unfinished search without new SSH calls. Both test-owned target workers reach terminal receipts. Real stdio restart continues to isolate its random native sessions.

This is an uninstalled source candidate. The live runtime/app, their credentials, Desktop Commander and protected production services are unchanged. It establishes neither installed model-origin acceptance, all-method authenticated caller isolation, per-caller job/PTY ownership, independent production recovery/rollback, business replacement, public OAuth/tenant isolation nor complete Desktop Commander replacement. Installed facade activation and any risky DC-off exercise remain separate gates. Desktop Commander stays available.
