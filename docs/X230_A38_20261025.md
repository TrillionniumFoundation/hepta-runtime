# X230 A38 integration and six-host file observation comparison

## Result and scope

A38 integrates the previously isolated A35 archive work, A36 opt-in file
observation pool, and A37 post-spawn reader-start recovery into one source tree.
All 165 source files are bound to the qualification receipt. The X230 formatting,
strict Clippy, all-feature test, and release gates passed after explicitly
invalidating the candidate package's copied Cargo cache.

The same qualified executable completed an **off/on/on/off** comparison of
`file_info` and `binary_read` across ai395, mac, main, pocket4, rog, and x230.
All **1,248 requests** passed their checks: 1,152 measured requests, 48 warmups,
and 48 negative cases. No request was automatically retried. The input files
were the six existing synthetic completed-job outputs, 44–48 bytes each; these
results describe observation latency and transport overhead for that workload,
not bulk file bandwidth or arbitrary application jobs.

The file pool remains opt-in. The result improves throughput and local process
tree CPU consumption, with a measured memory cost. No installed runtime or
controller service was replaced or restarted. This is a draft source checkpoint,
not a production rollout or evidence of host-reboot recovery.

## Source and behavioral changes

- `request_archive_content.rs`, `request_archive_index.rs`, and
  `request_archive_store.rs` retain complete original-record verification and
  namespace fencing. The large-archive path uses two bounded validation workers;
  all actual workers are joined before their capacity is released, including
  error paths. Metadata identity alone is not treated as a complete-byte proof.
- `request_usage_batch.rs` combines overlapping large-archive usage reads in a
  fixed 1 ms window while retaining each caller's owner, result channel, and
  original deadline. Small archives retain the direct path. Cached aggregates
  do not replace original-record verification.
- `--runtime-file-observation-pool` routes only `file_info` and `binary_read`
  through the existing bounded SSH observation transport. Root authorization,
  expected-version checks, complete content/hash validation, and response-size
  limits remain active. The flag requires the pinned observation profile; a
  stopped or invalid pool does not silently turn into an unpinned fallback.
- The established limits remain **8 global sessions, 2 per host, 8 queued and
  16 admitted requests**. This checkpoint does not adopt the earlier 12/4
  capacity experiment.
- If starting an output-reader thread fails after the workload was spawned,
  the supervisor signals the original unreaped child group, waits for the
  original child, and joins every reader it actually started. It preserves
  unknown effect outcome, incomplete capture, and no automatic retry. The
  ordinary leader-exit/inherited-pipe case is the subject of the separate A39
  follow-up; A38 does not claim that follow-up is already fixed.

## Fixed six-host comparison

Each of the four rounds used the same executable and the same six immutable
synthetic files. Only the file-pool flag changed. Per round, 96 measured calls
ran at each of C1, C4, and C8, with a balanced host/tool mix. Fresh controllers
were started and actually waited after stdin EOF. Known-host/config hashes and
the current SSH agent were pinned in a fresh private profile. The original
template was not edited; credentials were supplied through the existing agent
with temporary forwarding, without copying private keys.

The rate below is total successes divided by total measured wall time across
the two rounds in each mode. It is descriptive evidence from two observations
per mode, not a confidence interval.

| Concurrency | Pool off calls/s | Pool on calls/s | Throughput change |
| --- | ---: | ---: | ---: |
| 1 | 1.9731 | 3.9383 | +99.60% |
| 4 | 8.0790 | 14.8303 | +83.56% |
| 8 | 11.5433 | 21.5945 | +87.07% |

At C8, off-round p95 latency was 882.35/884.48 ms; on-round p95 was
445.67/427.88 ms. The first off C1 round had higher latency than the final off
C1 round, so the raw results and order are retained rather than assuming
stationary network conditions.

Every successful read was checked against the original expected bytes, file
size, SHA256, version, cursor, and EOF. Negative cases required the expected
stale-version and outside-root errors, not merely any failure. The complete
[report](evidence/x230-a38/file-abba-report.json) and
[request rows](evidence/x230-a38/file-abba-calls.jsonl.gz) retain all rounds,
warmups, measured rows, negative rows, and resource observation errors.

## Resource tradeoff

Whole-round `RUSAGE_CHILDREN` deltas, observed after waiting each controller,
cover that controller and the local descendants it reaped. They include
startup, warmup, measured calls, rejection cases, and shutdown. They exclude
remote host CPU and the external sampler's CPU.

| Resource | Pool off, two rounds | Pool on, two rounds |
| --- | ---: | ---: |
| Waited local process-tree CPU | 119.384782 s | 68.783497 s |
| Per-round sampled tree RSS peaks | 79,816 / 80,232 KiB | 110,904 / 112,264 KiB |
| Per-round sampled controller RSS peaks | 16,060 / 16,228 KiB | 17,160 / 17,188 KiB |

Local process-tree CPU decreased **42.39%** for the full fixed rounds. Pooling
moves SSH work into the controller, so controller-only CPU would be a misleading
comparison. The observed tree RSS peak increased by roughly 31 MiB. This is the
reason to keep an explicit file-pool choice for memory-constrained use.

The resource sampler is not exhaustive or atomic. Five distinct FD permission
errors were retained (some cell snapshots repeat the same accumulated error).
RSS and CPU were independently sampled where readable. FD observations are
incomplete and are not a proven descriptor limit. Every controller exited 0,
had no unmatched responses or reader error, and had no surviving descendant
among the processes the sampler had actually observed. This last check is not
a universal absence-of-processes proof.

## Remaining boundaries and next work

- This comparison measures tiny immutable file observations. Larger files,
  writes, transfers, mixed business workloads, and WAN changes require their
  own evidence.
- A35's historical small-archive guard had zero executed query rows because
  its prerequisites were missing. It is not a passing performance guard and
  is not described as thousands of executed failures. A fresh native MCP
  64-record hot C1 guard is being prepared separately.
- A39 addresses a normally exiting leader whose same-group descendant retains
  the output pipes. Its source and tests are isolated until qualification.
- Previous controller-crash recovery is not host reboot, storage power-loss,
  or general exactly-once execution of external effects. Unknown effects stay
  unknown; jobs are not automatically relaunched to manufacture certainty.
- Abrupt-exit socket roots still require durable original-child custody for
  automatic reclamation. This checkpoint does not delete old roots or signal
  reconstructed PID/PGID identities.
