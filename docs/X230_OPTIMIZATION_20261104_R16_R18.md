# X230 R16–R18：多机并发、吞吐与资源优化

> 最终采用 R18：生产源码仅修改 jobctl 的有界 JSON 缓冲读取。完整资格、35 项独立身份检查和最终六机恢复验收全部通过；主 runtime 与 native driver 的实际字节保持 R14。保留 workers2 / arena1，常态 observation 客户端并发优先 C8。R16 与整套 R17 的性能取舍不支持采用，完整证据保留。

## 目标与结论范围

本轮继续在 X230 上优化 HeptaRuntime，覆盖六个独立 host groups 的 native stdio MCP observation、线程配置、突发 admission、取消、SSH transport 中断及 controller 重启恢复。采用的基线是 PR #87 提交 `a784b92df7c84e6047343b436222716eb4b532d6` 中已资格的 R14 Rust 源码和 R15 可选 arena1 配置。

候选 R17 修改两个生产源码文件：`src/bin/jobctl.rs` 的 JSON 缓冲读取，以及 `src/mcp/runtime/jobs.rs` 中延后构造 legacy Python 分支专用的请求对象。R17 的最终多机数据没有支持整套采用，因此进一步收窄为 R18：仅保留 jobctl 的局部有界缓冲读取，主 runtime 源码保持 R14。R16 的路径预解析和 pin-set 缓冲复用、R17 的请求对象改动都保留为完整、可复核的未采纳实验。

这里的 native 吞吐是已完成作业的 `process_status` / `process_read` 调用吞吐，不能解释为启动作业、计算任务、远端成功取消或整个集群的计算吞吐。CPU/call 的主指标只计 controller，以同一 PID/start-ticks 的 `/proc` utime+stime 前后快照及单调时钟复算；CPU 采样区间包围整个 cell 窗口。它是包含 controller 全部线程、受 tick 精度限制的进程级摊销值，不是逐 RPC 的精确 CPU 归因。SSH、其他子进程、未知分类和采样缺失另外保留，不能把采样所得子进程 CPU 相加后宣称精确的集群 CPU。

## R17：JSON 读取和无用分配

### jobctl 的有界缓冲读取

原代码将文件直接交给 `serde_json::from_reader`，解析器对未缓冲文件产生大量小读取。改为：

```rust
Ok(serde_json::from_reader(std::io::BufReader::with_capacity(
    8192,
    f.take(INPUT_MAX + 1),
))?)
```

`Take` 放在 `BufReader` 内部，使物理预读取仍受原有 `INPUT_MAX + 1` 上限约束。保留 fresh open、O_NOFOLLOW / NONBLOCK / CLOEXEC、regular-file 和初始长度检查、EOF 与错误传播。没有修改全局 jobctl 锁、fsync 次序、witness、取消或 owner 检查。

原 `json_file` 本来就没有 after-read stat / 增长 fence、独立 hardlink / owner 验证、逐组件路径验证，也没有并发改写 snapshot 保证。本次不虚构这些保证；对稳定输入保留解析契约，buffer 会改变预读取时机，但不会增加物理读取上限。并发改写或任意注入 I/O 失败时，不能保证每个 interleaving 都与旧实现完全等同。

在 X230 上使用一份 release probe binary、8 种语义场景、4 个 ABBA blocks（共 128 timing rows），所有 blocks 的 CPU 均改善。8 个语义案例、18 个边界案例和 2 个 Take 上限模型全部等价。独立未计时的 Read oracle 在 5 个合法 JSON fixtures 上核验读取次数和相同消费字节。提前语法失败时预读取可能消费更多字节，但始终受内部 Take 上限约束。

该合成 fixture 的 completed status/read 组件分别节约约 0.362/0.364 ms CPU；64 KiB Spec 的解析阶段节约约 48 ms。**不能写成多机 MCP 吞吐提高 85%–99%。** 该路径属于 Linux isolated jobctl backend，正式六机 operator/Python observation 对照不会直接覆盖其线上收益。probe 复用实际函数并使用合成文件，running status 注入 probe closure；它不包括真实 sudo、systemctl、SSH 和全局控制锁。mini-program 与完整生产程序的 feature graph / whole-program 优化不同，精确源码、Cargo.lock、features 和命令均保留。

### 只在使用时构造 legacy 请求

`read_job` 原先无条件构造 legacy Python 请求 JSON，即使随后进入 native pool、Python pool 或 direct native 分支也会分配。R17 将构造移动到实际消费该对象的 legacy 分支。host/config 选择、offset 默认值和 clamp、owner/audit 顺序与错误契约保持原样。这是减少无用工作，不改变调度或并发上限。

每个 arm/C 的 rate 为该 campaign 两个 cells 的成功调用数之和除以耗时之和，CPU/call 为两个 cells 的 controller CPU 差之和除以调用数；p95/p99 是该 arm 两个 cells 的原始 latency 合并后的 nearest-rank。相邻配对为 B1/A0、B2/A3，每臂只有两个 controllers，不能称统计显著。100 ms 非原子资源采样可漏掉短命或已改变父进程的子代；SSH RSS 相加会重复计共享页，tree CPU interval delta 也不是严格下界。sampler 和 transport capture 的 Python CPU 不属于 controller CPU 主指标。

### C32 突发 admission

两轮突发分别在 7.910 / 8.617 ms 内发出 32 个客户端请求，而且所有请求均在首个响应前发出。两轮各 **16 个成功 +16 个精确 capacity rejection +0 个其他/未知错误**。拒绝文本固定为：

```text

```

分类器只接受实际 MCP native `isError=true`、单一 text content 和上述精确文本；一般错误不会被算成容量拒绝。32 个客户端 pending 不能推定 32 个 pool identities 已获 admission；内部 identity peak 没有遥测。

### 第一次资格失效：源码正确不代表执行产物正确

`qualification-01` 的格式、Clippy、测试和 release 命令都返回 0，原报告也写有 `qualified=true`，但独立身份核验发现实际 libtest、runtime 和 driver 仍是 R17 产物。准备 R18 时使用 `copy2` 保留了 R14 的旧 mtime，再复用刚编译过 R17 的 mutable target，Cargo 将相关根 crate artifacts 标记为 `fresh=true`。源码内容已经回退，旧产物却没有重编。这是本轮实际观察到的构建缓存失配，不能用绿色测试掩盖。

Cargo 官方对 [fingerprint freshness 的说明](https://doc.rust-lang.org/stable/nightly-rustc/cargo/compiler/fingerprint/index.html)包含源文件与 dep-info 的 mtime 比较；本轮的接受标准因此必须同时包含源内容、实际编译事件和实际产物身份。修正是在原源码字节和 mtime 不变的情况下，使用运行前确认不存在的 `target-fresh-02`，重新执行完整资格。原 target 和失效的 `qualification-01` 没有删除或覆盖。这是一次有明确原因、有独立编号的修正，不是把重复运行隐藏在成功汇总里。

## 停止决定与下一层边界

本轮保留了能证实收益且不改变现有语义的改动，拒绝了没有稳定整链收益、恶化尾延迟或改变权限检查行为的候选。现有固定 profile 每次 observation 的完整 pin-set 读取/哈希、持久化顺序和 cancellation/reap 生命周期仍保留。

更深的方向包括 durability group commit、owner 状态分片、长期等待专用执行机制和面向该 CPU 的编译变体。这些不是已验证成果：它们分别涉及 ACK/durability、锁与恢复次序、取消/physical reap 生命周期或二进制可移植性，需要各自新的设计与实验。`perf_event_paranoid=4` 也限制了本轮硬件级采样；没有通过更改机器策略扩大权限。

这里记录的是在明确机器、操作分布和现有契约内达到的可验证取舍，不宣称所有可能优化已经穷尽、绝对最优或 Pareto 最优。生产 Mac controller 和其他任务部署没有被替换；交付是 X230 上保存的资格产物、可复算证据以及 PR #87 中的源码与工具。
