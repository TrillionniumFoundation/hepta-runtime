# Native late-quote semantic research profile

This profile addresses a specific missing information path in the fixed SmallHCSN
six-tick evaluator. Its original receiver score cannot observe the final odd-tick
quote through the neural residual. A weight-only edit in the original mark scope
does not add that missing connection. The opt-in research graph ties the existing
four sender mark rows to the four receiver marks on the final tick. It changes
effective connectivity and is identified separately from the original graph.

The pure compiler maps each actual checkpoint's signed-head contrast to the sign
of that row's price coefficient. It reads no labels and takes no gradient steps.
Its monotonic real-arithmetic condition still requires complete F32 validation:
cancellation, saturation, inactive physical mass and score rounding can produce
ties. It is not a global weight-space optimum or a trading-profit certificate.

## Wire contract

`rea_model_session_weight` retains its existing F32 and sender40 wire shapes. The
third, separately admitted shape selects
`smallhcsn_late_quote_min_mark4_task_route_v1`. It has no caller source path,
executable, state directory, authority token or general graph description.

Operations are `late_quote_compile`, `late_quote_prepare`,
`late_quote_roundtrip`, and `late_quote_recover`. Preparation accepts one canonical
profile and HCSNIN1 batch for the late task, another for normal-route retention,
an accuracy goal from 1 to 100 percent, and an exact nonnegative F32 update radius.
Both batches bind the same twelve-tensor session source. The checked task requires
six ticks, two choices, nine inputs, a shared prefix, different final price column
7, identical other final inputs, equal external baselines and positive input
normalization scales. The accuracy targets are verified against the declared
lower-price task only after the label-free plan has been sealed.

The only mutable words are flattened indices 7, 16, 25 and 34 of
`body.input_mark.weight`. The header, readout, bias, other parameters, aliases and
physical buffers are preserved. The compiler is rerun on each admitted checkpoint;
it does not transplant another checkpoint's delta. All-zero signed-head contrast
causes an explicit abstention. This profile cannot edit an unspecified Belief,
Call/Put, learned Continuation Q or NDU controller.

Preparation binds both graph-only KEEP and the fixed sign program before any
forward or publication. SIGN is admitted only when its represented F32 update
fits the caller's radius. A zero radius still permits KEEP. If KEEP meets the
declared goal, no weight edit is selected. Otherwise SIGN is selected if already
admissible, and the workflow abstains without publication if it is not. No
measurement may enlarge the radius or replace the prebound program.

## Function identity and retention

A checkpoint hash does not identify the entire function. The saved plan and
atomic cohort manifest bind the graph, request route, evaluator source, actual
running executable, semantic task, and `fixed_reset_step0_six_tick_v1` initial
state contract. This profile reinitializes each six-tick rollout. It does not
capture a live neuron's evolving state or authorize an arbitrary live phase.

The candidate has two explicit routes using the **same selected weight bytes**:
the checked late task uses the bridge, while normal-route retention uses the
original graph. The workflow also measures the unconditional bridge on the normal
batch and reports that result separately. Passing conditional retention cannot
be presented as intrinsic, unconditional retention by the weight edit.

The existing immutable cohort store publishes the model and complete function
capsule together. Four expected-equals-replacement words represent a graph-only
candidate without relaxing the existing nonempty patch contract. A candidate can
therefore have the same weight SHA as its parent while retaining a different
artifact ID and function. The inverse must restore the original capsule even when
zero weight bytes changed. Both late and normal routes become Original after
restoration.

## Original owner, finite compute and recovery

The existing effect-owner admission, retained task, cohort lock, artifact quota
and journal quota remain in force. A separate closed saved schema records this
profile; the original sender40 authority and saved-schema checks are unchanged.
The saved plan binds both possible artifacts and an independent immutable seal
binds the complete attempt, including its original wall and Linux boot clocks.

One normal attempt has a 60-second window and three nonrefundable 20-second phase
groups. The parent group permits three full forwards; the candidate group permits
at most three; the restored group permits two. The maximum is eight complete
forwards. KEEP normally needs seven. A phase charge is durably written before its
first forward. A partial or lost group cannot be replayed or refunded. Records
distinguish completed forwards with durable results from unknown interrupted
work; the cooperative deadline is not an OS hard-real-time guarantee.

A one-shot decision binds the original parent observations, goal, plan, chosen
artifact and function before publication. Recovery verifies that decision; it
cannot select again, recompile, publish another candidate, or replay parent or
candidate work. It uses the original journal and plan SHA and retained artifacts,
so deleting the workspace source does not authorize a new attempt or prevent its
exact inverse. Recovery can run only a previously uncharged restored group within
the original window, on the same boot, source implementation and executable.
Expired, rebooted or changed-code attempts retain inverse authority without
receiving new model work.

All normal outcomes compensate through the canonical inverse, including rejected
candidates and caller cancellation after publication. Revocation blocks new model
work; it does not abandon the already admitted owner's narrow compensation.
Publication and inverse responses can be reconciled from their original durable
intents. There is no shared incumbent pointer, automatic retry, scheduled
research job, service deployment or production activation in this interface.

## Qualification boundary

The standalone research CLI has independent source and executable receipts for
full forwards, label-free scope, task re-binding, KEEP selection, conditional
retention and graph-plus-weight restoration. These engineering replays use
previously observed scientific inputs and are not new blind scientific tests.
Their receipts do not qualify this new MCP transaction or hard-crash recovery.

The MCP profile requires the repository's original exact-head and prospective
merge checks, both feature modes, isolated owner and recovery tests, and fresh
process crash controls. A source mapping entry remains an OPEN native interface
mapping until execution evidence supports a narrower qualification. Historical
REA evidence, upstream provenance and broader circuit understanding are not
silently requalified by this change.

CI's two isolated-test steps in each lane omit DWARF debug symbols. The integrated
debug test harness otherwise exceeds the 512 MiB executable-identity read cap.
Assertions, overflow checks, isolated processes, zero retries and the complete
feature matrix remain enabled. The entire actual executable is still freshly
hashed through the original cap; no test-only digest or expanded byte permission
is substituted. Release builds retain their original profile and command.
