# Literal single-file view search original reference

This harness executes unchanged Rust `render_view`, `view_existing_path`,
`view_file_with_content_search`, `Matcher`, `search_lines`, `execute_view`,
line identifiers, request context, and local I/O functions. Three explicitly
pinned files from the existing view-call oracle supply the test-only scheduling
harness and base source composition. The search extension replaces the former
unsupported-search stub with the exact original function and instruments the
original raw-byte read around its actual Tokio filesystem operation.

The corpus contains 72 calls: 71 literal searches and one separately identified
whole-file call that establishes a real nonempty session cache. Calls 10064–10071
share session 20000. Case 10066 is unbound; case 10067 aborts its real Tokio task
after the result gate and before publication. No expected text is generated by
Python. Inputs, every returned raw read snapshot, actual logical I/O observations,
full rendered text, visible result, and cache probes remain in the binary streams.

The public literal domain uses a nonblank UTF-8 content string, regex false, and
typed unsigned context. Values above i64::MAX follow the original Value::as_i64
fallback to zero. Endpoint values are present in one input to establish content
dispatch priority. Missing alternative paths containing `|`, directories, regex,
background URIs, remote paths and the public MCP router are outside this domain.
An existing ordinary filename containing `|` remains covered.

The two filesystem limits are exercised independently: the original 5 MiB
metadata precheck and the original 8 MiB successful-result gate. One synchronized
mutation grows a file beyond 17 MiB after its metadata observation. Three invalid
UTF-8 inputs expand to results immediately below, at and above the result gate.
This is original behavior, without a new cumulative read quota.

The runner creates a fresh target directory and executes three recorded processes:
Rust version, `cargo build --locked`, and the actual original replay. All have real
180-second deadlines, full stdout/stderr and input hashes. Offline mode is optional.
Cargo and rustc invocation paths remain absolute without resolving rustup symlinks.
Registry package versions and checksums must be a subset of the original lockfile.

`REFERENCE_READY` means original execution succeeded. A byte comparison still
requires the independent native producer's source, ELF and receipt admission.
Neither result claims the entire view tool or runtime has migrated.
