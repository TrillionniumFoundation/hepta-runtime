# Configuration aware HIA catalog qualification

This package is an isolated successor to the qualified eleven-tool catalog and the installed102 graph. It keeps all 391 private cases and 478 HIA calls, including the 87 retained cases and all 18 non-list operations.

The current public graph installs the original nine tools plus Batch. Its descriptor table ends at Authority slot56; it does not install Bellman slot57 or the SDK request registry slot58. Consequently the real public directory advertises ten tools when runtime configuration is present and seven when absent. It never advertises the uninstalled Bellman body.

The private catalog compares four installed masks: 0 is the original nine; bit0 adds batch_edit; bit1 adds weight_bellman_plan. All four masks are checked for flags 0,1,3,5,7,9,11,13,15. The runtime-presence bit is independent of the HIA, REA and weight-worker flags. Bellman belongs to the original runtime-tool group, not to the optional weight-worker group.

## Source and execution boundary

The current target is d3d75c30719db966b004756f610007a7c723729e. Its complete original server remains an unchanged prefix; the old append-only catalog observer is reused exactly. The additional public observer calls that original list handler and only retains installed Tool values. The actual RMCP 3.9.0 typed result and peer-policy serializer produce the comparison bytes. Fresh CI runs the full old 216 direct contexts, including resolved None and arbitrary ProtocolVersion strings, plus 1,728 actual SDK projections. Nine initialized public sessions retain 216 list requests: 162 reach the original handler and 54 are rejected by the actual SDK for unsupported explicit protocol versions. No request is dropped. Absence of request metadata falls back to the initialized peer version and is not labeled resolved None.

The native frontend obtains actual config through child6/global11 operation3. It owns all copied ID/meta/version spans across reallocations. Modern policy comes from the full resolved G2 version span and the qualified lexical policy, not from connection lifecycle flags. The real installed102 path selects installed mask1 internally; callers cannot select an installed mask through JSON.

## Adding an installed tool

A successor must first install and qualify the real tool route, body and required host resources. Then it must bind the exact current router declaration and category membership, regenerate the native policy/Value/SDK assets, extend the private installed-mask contract if necessary, and rebind the frontend's internal installed capability value. The current mask ABI only accepts 0..3 and the compiled table is intentionally finite. It is not a generic runtime plugin interface.

The original 136-declaration router is retained as a source and comparison input; this package does not claim that all 136 bodies are installed. The actual111 combination with Bellman requires a separate fresh graph and public lifecycle qualification.

## Deadlines and retained evidence

Each private native domain and complete public replay keeps its 180-second limit; every public exchange keeps 60 seconds. The old direct-reference Cargo build retains 1800 seconds and its outer 3600-second limit. The configured catalog workflow retains the existing catalog 60-minute job budget. There is no timeout increase or semantic subset.

All complete input/output/workspace buffers, all compiler output tails, actual process streams, full original sources and locked crate archives are retained. The read-only phase checks physical mutations and the full tree before and after, permits no HIA/Rust execution and writes no report. Its parent separately retains the finished stdout after the guard ends. The complete archive is split into 384 MiB compressed pieces without dropping bytes.

The first source-only admission failed because a new common.py shadowed an unchanged retained module. That failed job is preserved in ci/SOURCE_FAILURE_V1.json. The correction only renames the new wrapper to catalog_ci_support.py. A source checkpoint or a successful build is not a semantic PASS.
