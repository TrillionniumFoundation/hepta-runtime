# Private audit record I/O qualification

This successor implements the actual target request_audit.rs record I/O decisions in one HIA owner, and calls the already qualified audit_json HIA owner for typed Record decoding and encoding. The 16 original Rust functions and their complete types are retained byte for byte. The first source-author attempt is retained as a failure; the second author completed with 43 functions, 1,040 blocks and 3,810 operations.

The fixed input-only corpus has 219 filesystem scenarios and 459 operations. It includes persistent save/read/replace/remove sequences, inode modes, hard-link and staging cleanup, complete JSON size boundaries, exact record bindings, and error recovery. Native execution captures every entire input/output/workspace, including guard and unused bytes. Both implementations use the same absolute fixture path in successive, reaped processes. Filesystem observations include every entry, full file content, permissions and hard-link relationships. An independent strace of the unchanged original records the actual durable write/sync/link/unlink/rename order. The reader compares that order and every terminal frame and filesystem observation.

Python in this package is an explicit qualification transport and observer. All audit decisions, UTF-8 checks, retry decisions, publication choices and cleanup sequencing stay in HIA. This private result does not itself provide the final native callable filesystem pump, begin/finish caller, HOT_CACHE, archive-store composition, concurrent/crash-recovery qualification, or a public handler. These remain separate work. JSON rejection is carried as an error category; the actual original Display/debug/chain strings remain complete in evidence, but this owner does not claim to render every Serde diagnostic string.

Fresh HIA compilation uses the pinned compiler source and independently captures B1/B2/B3. This is development fixed-point evidence, not a new compiler cold-gate qualification. Rust runs only in CI under Rust 1.95.0 with the exact target package lock records and explicit development profile. Native replay has 180 seconds, the original child has 60 seconds (its straced observation process has 180), pure reader and physical-control processes have 180 each, compiler/reference builds have 900, and the CI job has 15 minutes. No deadline is raised on failure.

The strict reader requires all source, registry archive/source bytes, actual compiler receipts and stdout, complete compiler output tails, actual process streams, native buffers, effects, filesystem observations and original syscall trace. Fourteen physical rehashed refusals and two independently copied admissions preserve the same corpus. The reused fixed-reader guard checks complete bytes and metadata before/after and exercises all twelve refusal branches. Report files are written only after the guard exits; the pure read APIs do not write or execute HIA/Rust.

All public-handler and whole-runtime qualification flags remain false.
